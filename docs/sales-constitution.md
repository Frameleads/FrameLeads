# Company Sales Constitution

The Sales Constitution is a tenant-owned set of hard sales boundaries. It is separate from FrameLeads Brain (company facts), Revenue Playbook (handling preferences), and Prospect Memory (prospect history). Where Playbook advice conflicts with a hard rule, **Constitution > Playbook**. This release does not compose those services into a decision engine.

`SalesConstitution` holds one root and monotonic `revision` per user. `SalesConstitutionRule` holds tenant-scoped rule identity, category, effect, severity, scope, bounded description, typed JSON constraint, applicable action types, priority, enabled/archive state, rule revision, and provenance. A composite foreign key binds a rule's `userId` and `constitutionId` to the same tenant. `SalesConstitutionRevisionEvent` records each changed rule's bounded before/after policy fields, rule ID, tenant, root revision, change type, timestamp, and authenticated actor ID in the same transaction as the mutation. Existing `GovernanceRule` remains untouched: its current `trigger`/`response` records feed governance institutional-memory metrics and are not structured hard policies. The existing outbound throttle's daily cap also remains separate. No legacy records are automatically translated into constitutional rules.

Categories: CLAIM, PRICING, DISCOUNT, COMMERCIAL_TERM, LEGAL, COMPLIANCE, SECURITY, PRIVACY, DATA_HANDLING, CONTRACT, CAPABILITY, COMPETITOR, OUTREACH, UNSUBSCRIBE, COMMUNICATION, COMMITMENT, APPROVAL, CUSTOM. Effects: BLOCK, REQUIRE_HUMAN, REQUIRE_APPROVAL, REQUIRE_SAFE_RESPONSE. Severity is LOW, MEDIUM (default), HIGH, or CRITICAL; it describes importance independently of priority (1–3). Scope is GLOBAL (default), OUTBOUND, REPLY_DECISION, PRICING, COMMERCIAL, LEGAL, COMPLIANCE, or SECURITY. Action types and scope together define applicability. These are constraints, not workflow execution or automation modes. New rules have server-owned `USER_ENTERED` provenance; `SYSTEM_DEFAULT` is reserved and not populated.

Structured constraints are a small validated union: `DISCOUNT_PERCENT` (`threshold`, `GT`/`GTE`), `MIN_CONTRACT_MONTHS` (`minimum`), `PROHIBITED_CLAIM` (bounded phrase list), `TOPIC` (explicit category), `UNSUBSCRIBE` (confirmed opt-out), and `CUSTOM_MANUAL`. The last kind is preserved in context but never reported as machine-compliant. Numeric values, categories, action types, lengths and object keys are validated. Claim phrase matching is literal case-insensitive substring matching, not a semantic capability classifier; callers must supply a trusted proposed-claim string. Existing Brain capabilities are not copied into Constitution.

`evaluateSalesConstitution({ userId, action })` accepts only a bounded structured action: action type, optional scope, discount percent, contract months, proposed claim, topic, and `unsubscribeConfirmed`. It is **read-only**, including for an uninitialized tenant, and paginates **all** enabled action-applicable rules; it does not use the bounded context cap for enforcement. GLOBAL rules apply to any action scope. A different explicit scope is out of scope. If action scope is missing, a relevant scoped rule is unresolved rather than skipped. Matched BLOCK rules return `BLOCKED`; other matched effects return `REQUIRES_REVIEW` with distinct approval, human and safe-response arrays. Missing facts for an applicable rule return `unresolvedRules` and `REQUIRES_REVIEW`. An uninitialized Constitution returns `configurationMissing` and requires review. No rule executes a send, approval, escalation, route, mutation, or model call. The same evaluator accepts production or synthetic dry-run inputs; no simulator is implemented here. A caller may treat `ALLOWED` as permission under the **configured, applicable** rules only, not as proof that all legal or business requirements are satisfied. The method is domain-level; no public evaluation endpoint is exposed yet.

Every relevant rule gets a bounded trace entry with rule identity, category, scope, severity, priority, effect, machine-evaluable flag, scope/action/constraint condition results, match status, and final winning/subordinate/unresolved result. The response includes Constitution revision, authority, winning rule/effect, precedence explanation, and `unresolvedPotentiallyOverrides`. An unresolved higher-precedence rule keeps that uncertainty visible even when another rule matches.

Precedence within Constitution is deterministic: restrictive effect (`BLOCK` > `REQUIRE_APPROVAL` > `REQUIRE_HUMAN` > `REQUIRE_SAFE_RESPONSE`), then severity (`CRITICAL` > `HIGH` > `MEDIUM` > `LOW`), then explicit priority (3 > 2 > 1), then ascending rule ID. Effects may produce cumulative requirements; `winningRule` identifies the dominant rule, not a workflow action. The exported authority contract orders **hard safety/compliance constraints > Sales Constitution > future risk controls > Revenue Playbook > Brain communication preferences > AI recommendation**. Neither Playbook guidance nor AI output can override a Constitution result. Orchestration is deliberately deferred.

`detectConstitutionConflicts({ userId, constitutionId? })` reads all active tenant rules. It reports incompatible effects only when scopes and action types overlap and a typed condition has a proven overlap: identical discount comparator/threshold, identical contract minimum, common prohibited phrase, identical topic, or confirmed unsubscribe. It does not call rules conflicting merely for sharing a category. Distinct discount tiers, compatible cumulative effects, and non-evaluable custom rules do not produce invented conflicts. Each conflict includes both rule identities/effects/severities/priorities, overlap reason, and a deterministic winner under the same precedence order. Conflict analysis does not mutate data or call providers.

Unsubscribe detection in inbound processing is not a canonical durable opt-out record. Consequently the evaluator requires an explicit trusted `unsubscribeConfirmed` value from a future caller and does not infer it from raw reply text or maintain a second opt-out state. Unknown opt-out state remains unresolved when an unsubscribe rule applies. Future Inbox Triage may supply structured topics and canonical opt-out state; it is not implemented here. Future Automation Modes may operationalize a `REQUIRE_*` result; they are not implemented here.

`getSalesConstitutionContext({ userId, purpose?, categories?, maxRules?, maxCharacters? })` selects enabled, non-archived rules. It reserves candidate capacity for explicit categories and BLOCK effects, then sorts by explicit category, purpose relevance, effect restrictiveness, severity, priority and stable ID. It includes severity and scope in each selected row and rendered text. It caps candidates at 100, selected rules at 10, per-rule text at 700 characters and total text at 5,000 characters. This is **context retrieval only**, not complete enforcement. Root revision increments when active policy changes (active create/edit, enable/disable, active archive); reads, unchanged writes and edits to disabled rules do not increment. Rule revision tracks any actual rule edit or archive. A changed disabled rule can have an audit event at the unchanged root revision. No-op saves and reads produce no audit event. Future decision systems should record the returned root revision; Decision Replay is not implemented here.

The minimal authenticated editor is at `/dashboard/constitution`, linked from Revenue Playbook. It exposes severity, scope, and simple conflict warnings. API routes derive the tenant from the existing session and whitelist incoming rule fields. The `User` model has no owner/admin/member hierarchy. All authenticated tenant users share the tenant identity; `authorizeConstitutionMutation` centralizes this current rule and rejects a mismatched actor ID so future role checks have one entry point. Audit history is tenant-scoped through `listConstitutionRevisionEvents`; no public history editor is exposed. The schema migration is additive and must be deployed through the normal reviewed deployment process; this coding task did not deploy it. There are zero Gemini, Claude, OpenAI, embedding, or other provider calls and no AIUsageEvent writes.
